Introduction

This customer was migrating from Appfolio and had previously used Echo Sign (now part of Adobe) for document signing, so several of their questions were direct comparisons: what Rentvine does differently, and where the two systems' mental models don't map cleanly onto each other. Those comparison questions are exactly what surfaced the details below — they're the kind of limitation or mechanic a trainer usually only discovers when a customer coming from another platform asks "does it also do X?"

Quick Recap: What RU Already Covers

These points came up again on this call but RU already has solid coverage — don't re-teach them as new, just reinforce them:

  • RentSign templates, hot fields, and signing order (Week 6): already covered in depth, including that a document only inherits hot-field data when generated from inside the specific property, portfolio, or lease record.
  • Monthly and move-in charges auto-populating lease documents (Week 6): RU already teaches that Rentvine's designated monthly-charges field and move-in charge list aggregate fees automatically, rather than requiring them to be listed line by line the way some legacy systems require.

RentSign Does Not Support Conditional Logic

A customer asked whether RentSign can branch a document path based on a prospect's selections — for example, routing to a different disclosure page depending on an answer given earlier in the signing flow. It cannot. RentSign templates rely solely on an uploaded document plus fillable/hot fields; there's no conditional or branching logic layered on top.

This is a fair question to expect from customers coming off contract-builder tools like Echo Sign/Adobe Sign that do support conditional logic, so it's worth stating up front rather than letting a customer discover the limitation mid-build.

RentSign doesn't support conditional logic — there's no way to branch the document based on an earlier answer. If you need different disclosures for different scenarios, the workaround is either separate templates per scenario, or bundling every possible disclosure into one packet and letting the sender choose which pages to include before sending.

Standardizing Signature Field Font Size

RentSign doesn't offer automatic grid-locking or alignment for signature and fillable fields — placement is manual. It does, however, let you standardize the font size across fillable fields (the customer's call used size 14 as the example), which gives a document a more consistent, professional look even without automated alignment.

Swapping a Template's Background PDF: The Replace Form Feature

When the underlying document behind a template needs to be revised — a new PMA version, an updated disclosure form, a corrected lease template — the whole template does not need to be rebuilt from scratch. Under Document Management, the Replace Form feature (with left/right replacement arrows) swaps the background PDF while keeping previously placed hot and fillable fields intact.

One caveat worth setting expectations on: if the new PDF's page dimensions differ even slightly from the original, field positions may need minor manual adjustment after the swap. It's still far faster than recreating a template, but it isn't guaranteed to be pixel-perfect automatically.

You don't have to rebuild the whole template when the document changes — use Replace Form to swap in the new PDF and your fields carry over. Just do a quick pass afterward in case the new document's page size shifted anything slightly.

Tenant Portal Payment Routing: "Make a Payment" vs. "Pay Deposit"

A customer coming from Appfolio raised a real concern: lump-sum move-in payments that combine rent and a security deposit had previously created accounting complications when they landed as a single undifferentiated payment. Rentvine's tenant portal addresses this with two distinct payment options:

  • Make a Payment — deposits funds into the rental trust account.
  • Pay Deposit — routes funds directly into the security deposit/escrow bank account.

If a tenant pays a combined total (for example, $2,100 covering rent plus a $1,000 deposit) through a single payment, Rentvine applies the funds across all unpaid charges on the lease rather than guessing which bank account each portion belongs in. The cleaner outcome comes from tenants using Pay Deposit first to clear the deposit charge, then paying the remaining move-in balance separately — that keeps each payment routed to the correct bank account from the start.

Encourage tenants to use Pay Deposit first for the security deposit, then Make a Payment for the rest. If they pay everything in one lump sum instead, the system will still apply it to the open charges, but it won't necessarily land in the bank account you'd expect for each piece.

When Funds Land in the Wrong Bank Account

This is the mechanical detail that matters most for accounting staff: reallocating a payment's charge assignment inside Rentvine (via the tenant receipt's "applied to" section and the Reapply action) does not move real money between bank accounts. If a payment actually deposited into the rental trust account but should have gone to the security deposit/escrow account (or vice versa), correcting the ledger allocation alone leaves the cash sitting in the wrong account.

The only way to fix that is a manual bank transfer between the two accounts to match what the ledger now says. This is the same underlying mechanic RU already teaches for Escrow Mismatch corrections in Week 14 (Diagnostics) — this call just surfaces the tenant-payment-specific version of it.

Reapplying a payment to a different charge changes what the ledger says happened — it doesn't move the actual cash. If the money landed in the wrong bank account, you still need a manual bank transfer to true it up, the same way we handle an escrow mismatch.

Sending Application Invitations During a Data-Migration Gap

Customers transitioning from another platform (Appfolio, in this case) sometimes need to send a prospective tenant an application link for a unit that's still mid-migration and not yet fully built out in Rentvine. The workflow: go to Screening > Applications, click the green Actions button, and select Send Invitation. Filling in the specific unit, rent, deposit amount, and applicant details lets the invitation go out even while the property record is still being finalized.

This is a useful workflow to have ready specifically for onboarding/migration-period conversations, separate from the standard post-go-live screening flow RU already covers.

Troubleshooting: A Document Isn't Correctly Attached to the Lease

A live troubleshooting call, "Customer Education Training Call QA 3 — Fabiani Realty" (Sept 24, 2026), worked through a real symptom worth recognizing: a RentSign document generated with a name that's missing the lease address, which is a sign it was never properly attached to the lease it was meant to belong to. The fix sequence surfaced on that call:

  1. Click New Document from the lease.
  2. Give the document a clear, correct name (one that includes the lease/property address).
  3. Set the document type to Lease.
  4. Select the correct tenant.
  5. Pick the correct template.
  6. Click Create — this regenerates the document's hot fields correctly against the lease record.
If a document's name doesn't include the property address, that's your signal it isn't properly attached to the lease. Don't try to patch the existing one — start a New Document, name it clearly, set the type to Lease, pick the tenant and template, and Create. That regenerates the hot fields correctly.

The same call surfaced two related mechanics worth knowing alongside that fix:

  • Security deposit hot field for a tenant who already paid: rather than leaving a stale dollar amount on a regenerated document, set the hot field to $0, delete the hot field entirely, or convert it to a plain text box that says something like "already paid."
  • Tenant signature blocks are driven by template settings, not per-document edits: how many tenant "parties" sign a document is configured in the template's RentSign settings. Manage the number of signing parties there, rather than trying to manually adjust signature fields on an individual document.

This call also reinforced (not new, but worth restating alongside the fix above) that a renewal document should be uploaded and marked with document type Renewal in global settings so it flows through Rentvine's built-in renewal workflow rather than sitting as an unrecognized document type.
