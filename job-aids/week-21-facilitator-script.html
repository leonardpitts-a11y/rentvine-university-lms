Balance Forward Workbook, Data Migration & Reconciliation

Introduction

Last session we covered the customer-facing side of financial onboarding: the four-step timeline. Today we go under the hood into the actual mechanics -- the Balance Forward Workbook, how data gets migrated or entered, and how we prove a beginning balance is correct.

The Balance Forward Workbook: Two Templates

Which workbook template we use depends on one thing: is the client keeping their existing bank accounts, or opening new ones? The two templates account for uncleared transactions differently depending on that answer, so picking the right one first matters before any numbers go in.

Building the Workbook: A Real Example

Let's walk through a real example the way it actually gets built. Say the bank balance as of the cutoff date -- August 17th, for example -- comes back at $5,650. That single number has to be broken down into everything it represents.

On the Sign-Off Sheet, that $5,650 balance gets allocated out: Rental Trust operating balances split across each property (say $500 for two separate properties), Security Deposits organized by lease and further split by deposit type -- pet, cleaning, key/fob, last month's rent, and so on (for example, $1,800 for one tenant and $1,700 for another), and Tenant Prepayments (say $1,150 for one tenant) -- allocated until the variance against the bank balance hits exactly zero.

We start with one number from the bank, and we don't stop until every dollar of it is accounted for somewhere in the workbook -- trust, deposits, or prepayments -- and the variance reads zero.

Separately, the workbook also captures anything that doesn't touch the bank balance but still needs to exist in Rentvine: unpaid tenant charges, unpaid vendor bills, vendor credits, and owner/vendor 1099 income for the current tax year.

Once the workbook balances, it goes to the customer for sign-off. That sign-off is what lets us import balances with confidence instead of guesswork -- and it scales. We've reviewed a real sample workbook from a client with roughly 1,800 properties that used this exact same methodology.

What Migrates and Affects the Bank Balance

Security deposits, tenant prepayments, and uncleared items like outstanding checks or deposits all migrate and directly affect the client's starting bank balance. These are the categories that make up the variance we're solving for in the workbook.

What Migrates but Doesn't Affect the Bank Balance

Unpaid tenant charges, unpaid vendor bills, vendor credits, and owner/vendor 1099 income all migrate into Rentvine so they're tracked going forward, but none of them move the client's starting bank balance. They're recorded for future processing, not for the balance-forward math itself.

What Doesn't Migrate at All

Detailed historical ledger data -- individual payment and charge history going back multiple years -- doesn't migrate into Rentvine's ledgers. That doesn't mean it's lost: customers can keep it as an external file attachment inside Rentvine for reference.

Recording a Manual Balance Forward in Rentvine

For smaller accounts, balances get entered manually rather than imported. There are two ways to do this, both under Accounting:

  • Create a Journal Entry (Accounting → Transactions → Actions → New Journal Entry): set the ledger, set Date Posted to the cutoff date, add a description like "Balance Forward," then enter a debit or credit against an equity account (an Opening Balance / Balance Forward account) and the offsetting entry against the bank account.
  • Record an Owner Payment (Accounting → Money In → Actions → Record Owner Payment) when the money needs to show as deposited into a bank account. When you use this path, the payment must also be recorded as a New Deposit to complete the opening balance reconciliation -- that's the required second step, not optional.

Never enter prepayments or security deposits on the portfolio ledger -- those belong on the tenant/lease ledger instead, using the separate tenant balance-forward flow.

Importing at Scale: The Import Security Deposits Tool

For larger accounts, we don't hand-enter every deposit -- we use the Import Security Deposits tool under Global Settings. The source is a Security Deposit Import Sheet: a structured spreadsheet using the raw database field names the system needs for ingestion. Upload the CSV, and the import maps each row to the matching property and lease in Rentvine.

The Address-Matching Failure Mode

Here's the single most common reason an automated import fails: address-format mismatches. If the import file lists a property as "123 Main Road" and Rentvine's own record has it as "123 Main RD," the import won't recognize them as the same property.

If an import comes back with a property that didn't match, check the address format first -- nine times out of ten it's "Road" versus "RD," not a real data problem.

The fix is a manual correction in the source file -- update the address format so it matches Rentvine's record exactly -- and then re-run the import. It's not a system error and it's not something you fix by simply retrying.

Verifying the Import

After a successful import, don't just assume it worked -- verify it. Open the affected tenant's ledger and confirm the newly generated lease charges and receipts are present and correct. That's the real confirmation the import landed where it should.

Finishing with Bank Reconciliation 2.0

Once every recorded balance-forward item is in Rentvine -- manual journal entries, owner receipts and deposits, imported security deposits, manual prepayment receipts -- the last step is opening Bank Reconciliation 2.0 and checking off each of those items one by one.

When every item is checked off and the variance clears to exactly $0, that's the real finish line. A $0 variance at this step is what confirms the client's starting balance now matches their actual bank statement -- not before.

Core Data Has to Exist First

None of this works without core data already in place. Portfolios, owners, properties, tenants, and vendors all have to exist in Rentvine before any financial data can be imported or entered -- core data is what creates the ledgers that the workbook's balances get mapped onto. Without it, there's nowhere for those numbers to go.

Timeline and Scale

Onboarding completion typically takes 1 to 7 business days, depending on account size, the quality of the client's prior records, and how quickly they respond to requests. The workbook methodology itself doesn't change with size -- we've used this same approach on accounts from a handful of doors up to roughly 1,800 properties.

Closing

That's the full mechanical picture behind the customer-facing timeline from last session: build the workbook against one bank-balance number, know which of the three migration buckets each item falls into, enter or import the data with core data already in place, watch for the address-matching failure mode, and finish with Bank Reconciliation 2.0 clearing the variance to zero.
